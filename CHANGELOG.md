### Added

- Declarative endpoints: subclass `ClientX` and decorate methods with `get`, `post`, `put`, `patch`, `delete`, `head` or `options`. Path templates such as `/users/{user_id}` are filled from method arguments. The path defaults to `""`, so `@get()` calls the base URL, or on a resource, its prefix.
- Endpoints are checked when the class is defined, not on their first call: a path or resource-prefix placeholder that names no parameter raises `MissingPathArgumentsError`, and a missing positional first parameter for the client, or a `*args` or `**kwargs` parameter, raises `EndpointSignatureError`. The first parameter can have any name. Annotations are evaluated then too, so endpoints work in modules with `from __future__ import annotations`, and each endpoint's parameters are analysed once rather than on every call.
- Path values are converted like query values and percent-encoded, so a value can't add path segments, a query string or a fragment, or move up the path with `..`. `{name:path}` keeps slashes for values such as file paths; any other converter raises `PathTemplateError` when the class is defined. A `None` or empty path value, or a `{name:path}` value with an empty segment, raises `PathValueError` before anything is sent, instead of calling a different path.
- Request building from parameter names (`params`, `json`, `headers`, `data`, `files`), from request-part annotations such as `Annotated[int | None, Query("userId")]` (also through `type` aliases), and from Pydantic models, which are dumped in JSON mode and by alias unless `DumpConfig` says otherwise. A single query parameter, header or form value is sent under its `key`, or under its parameter or field name. `None` values are left out of query parameters, headers and form fields, so optional parameters and filter models can default to `None`. JSON bodies keep `null`.
- Parameter descriptions: every request-part helper takes `description=`, and `PathParam(description=...)` describes a path parameter, so a parameter doesn't need `pydantic.Field` to be described. The description goes into the JSON Schema of the parameter or model field, which is where AI tool and MCP schemas get it. `Field(description=...)` still wins if both are given. A `PathParam()` parameter without a placeholder raises `EndpointSignatureError` when the class is defined.
- Request-part helpers: `Query`, `Header`, `Form`, `Body` and `File`, named like FastAPI's, send a parameter or model field to that part, with an optional `key` for query parameters, headers and form fields. A helper wraps the whole type (`Annotated[int | None, Query()]`); one nested inside another type, or a second helper, raises `MisplacedHelperError`. On a model field, `Body()` and `File()` merge the value into that part, so a value that isn't a mapping or a model raises `UnconsumableArgumentError`.
- Opt-in argument validation: with `validate_arguments=True` on the client or an endpoint, each argument is checked against its annotation, strictly and including `Field` constraints, before the request is sent. A mismatch raises `ArgumentValidationError`. Values are never converted, and defaults aren't checked.
- Errors for failed requests: a 4xx or 5xx response raises `httpx2.HTTPStatusError` from any endpoint, with the body already read and before any decoder runs. Turn it off with `raise_for_status=False` on the client, or set it per endpoint with the decorators' `raise_for_status=` option.
- Typed responses. Type checkers verify that each method's return annotation matches its decoder. Built-in decoders: `ModelDecoder`, `TypeAdapterDecoder` (with `key=` to validate one member of a JSON object), `FromResponseDecoder`, `json_decoder`, `text_decoder` and `content_decoder`.
- Streaming with `StreamLinesDecoder`, `StreamChunksDecoder` and custom `StreamDecoder` subclasses. ClientX releases the connection when iteration ends. `StreamResponseDecoder` returns the open streamed response, which the caller reads to the end or closes.
- Endpoint options: tags (which `list_tools()` can filter by), per-endpoint timeouts, and deprecation warnings with `DeprecatedMessage`.
- Resources: group endpoints into `Resource` classes with a shared path prefix and tags, and mount them on a client (or nest them) to call them as `client.users.retrieve(...)` through the client's connection.
- Client classes can ship their own base URL and `User-Agent` as class arguments, `class ExampleAPI(ClientX, base_url="https://api.example.com", user_agent="example-api/1.0")`, so callers can create them with `ExampleAPI()`. Arguments given when creating the client win.
- Async clients: subclass `AsyncClientX` instead of `ClientX`, and write endpoints as `async def` methods with the same decorators, then `await` them: `user = await api.users.retrieve(42)`. It's built on `httpx2.AsyncClient` and takes the same class arguments and options, and `async with` or `aclose()` closes it. `AsyncResource` groups `async def` endpoints the way `Resource` groups `def` ones. Type checkers check an `async def` endpoint's awaited type against its decoder, as for a `def` endpoint, and both they and ClientX (when the class is defined) reject an `async def` endpoint on a `ClientX` or `Resource`, or a `def` endpoint on an `AsyncClientX` or `AsyncResource`.
- Clients close their connections at the end of a `with` block, or with `close()`. The underlying `httpx2.Client` is internal, so endpoints can use names such as `client` and `user_agent`.
- AI tools: `clientx.tools.list_tools()` describes a client's endpoints, including those on resources, as tools with JSON Schemas for arguments and results and safety hints from the HTTP method. `Tool.call()` validates a model's arguments and runs the endpoint through the client.
- MCP adapter (the `mcp` extra): `clientx.mcp.run_mcp_server()` serves a client's endpoints as MCP tools over stdio, only the read-only ones (GET, HEAD, OPTIONS) unless you pass `read_only=False`, with method-based tool annotations, structured results, and errors returned as tool results. A 4xx or 5xx error result has the status, method, path and start of the response body, but not the request's host or query string, so credentials in query parameters don't reach the model. `create_mcp_server()` returns the server for other transports.
- `llms.txt`: a compact guide to ClientX's patterns and pitfalls for AI coding assistants.
- A `ClientXError` base class for all ClientX exceptions.
- Structured debug logging: one `DEBUG` record per endpoint call on the `clientx` logger, with `clientx_*` attributes for the endpoint, method, path, request parts, status, elapsed time, and error. Values such as header values, bodies, and query strings are never logged.
- Support for Python 3.12, 3.13 and 3.14, with inline type information (`py.typed`).
