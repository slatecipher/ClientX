# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ClientX is a library for typed, declarative HTTP API clients on Python 3.12+. Subclasses of `ClientX` declare endpoints as decorated methods with empty bodies. The decorator reads the method's signature and annotations and builds an `httpx2` request from them. It depends on `httpx2`, which is a separate package from `httpx`, and on `pydantic` v2.

## Commands

All tooling runs through `uv`:

```bash
uv sync --all-groups --reinstall-package clientx   # install/refresh deps + the package
make lint             # ruff format + ruff check --fix on src, test and examples
make lint-ci          # check-only variant used in CI
make typecheck        # pyright src + test/test_typing.py + examples, then mypy on test/test_typing.py (gates CI)
make typecheck-tests  # pyright test (advisory only in CI, never blocks)
make test             # pytest (coverage flags come from pyproject addopts)
make check            # lint + typecheck + test

uv run pytest test/test_request_factory.py                  # single file
uv run pytest test/test_clientx.py::test_name               # single test
uv run pytest -k "deprecat" --no-cov                        # by keyword, skip coverage
```

- `uv sync` installs the package in editable mode (a `clientx.pth` pointing at `src/`), so `src/` changes apply right away. `clientx.__version__` is read from installed metadata (`importlib.metadata`), so after changing `pyproject.toml` (version, dependencies, entry points), rerun `uv sync` with `--reinstall-package clientx`.
- Ruff uses a 120-character line length and preview mode with a broad rule set: `S` (bandit), `B`, `N`, `C90`, `BLE`, `UP` and others. `S101`/`S105` are ignored in `test/`.
- Pyright checks `src` in **strict** mode (`strict = ["src"]`) and tests in `standard` mode. New code in `src` needs complete annotations. Empty containers need explicit types (`parts: list[dict[str, Any]] = []`), and dataclass default factories need explicit types (`field(default_factory=dict[str, Any])`). Running `pyright src` on the command line overrides the wider `include` list in `pyproject.toml`.
- pytest is configured in the native `[tool.pytest]` table in `pyproject.toml`. It runs with `strict = true`, so an unregistered marker, a duplicate parametrize ID, an `xfail` test that passes, or a config warning is an error; register any new marker under `markers` there. It also runs in its recommended `importlib` import mode (in `addopts`), so test modules can't import each other or a helper module. Shared test helpers are fixtures in `test/conftest.py` that each return a function: `endpoint_of(API.method)` returns an endpoint's `Endpoint`, and `mock_transport(sent, handler=None, *, status=200, **response)` records each request in `sent` and answers it without a network. A test takes them as parameters, and a file's own client builder that needs one is a fixture too (`make_api`, `make_recording_client`). Send requests through `mock_transport` rather than patching `send_request`; `httpx2.MockTransport` serves async clients too. Async tests use anyio's pytest plugin (`pytest.mark.anyio`, on the asyncio backend), which comes with httpx2, so it needs no dependency or marker registration; `test/test_async.py` marks the whole module. A test module's `__name__` is `test.test_<name>` in this mode, so don't hard-code module names in assertions. `test/test_typing.py` keeps its own transport, because `make typecheck` checks that file on its own.
- `test/test_typing.py` checks that decorated endpoints keep their signatures for type checkers, under both pyright and mypy (`[tool.mypy]` in `pyproject.toml` checks only that file, in `strict` mode, for Python 3.12). It uses `assert_type`, plus one comment per checker on each call that must be rejected: `# type: ignore[code]  # pyright: ignore[rule]`. An unused ignore is an error for each checker. Pyright has `enableTypeIgnoreComments = false`, so it never reads mypy's comments; elsewhere in `test/`, suppress pyright with `# pyright: ignore[rule]`, not `# type: ignore`. mypy's `empty-body` check is off in that file, as `docs/endpoints.md` tells mypy users to do. Pyright normally hides an untyped decorator by falling back to the undecorated signature, so that file enables `reportUntypedFunctionDecorator`. The fallback would hide regressions that mypy users see as `Any`.

## Architecture

The public API is `clientx/__init__.py`, which also re-exports `httpx2.Response` and related types, plus the `clientx.methods`, `clientx.decoders` and `clientx.exceptions` modules. Modules whose names start with `_` are internal.

**Decoration time** (`_decorators.py`, `ApiMethod.__call__`): each verb decorator does the following:
1. Builds an `Endpoint` (`_endpoint_context.py`) that holds the method, a `URLPath` template, the decoder, the deprecation hook, tags and the timeout. `Endpoint.stream` is derived from the decoder: `StreamDecoder` and `AsyncStreamDecoder` subclasses and `StreamResponseDecoder` stream; there is no `stream=` option.
2. Sets `endpoint.func = wrapper`. The `func` setter analyses the function once, like FastAPI's `get_dependant`: it captures the signature, resolves the return type with `get_type_hints`, validates the decoder, replaces the signature's parameter annotations with `get_type_hints(include_extras=True)` (so `from __future__ import annotations` keeps helper metadata), and stores the plan: `endpoint.client_parameter` (the first parameter, by position, whatever its name) and `endpoint.parameters` (the rest, as read-only `NamedAnnotation`s). It also checks that every path placeholder names a request parameter; the `path` setter repeats that check once `func` is set, so a `Resource` prefix is covered. As a result, `MissingReturnTypeError`, `MissingDecoderError`, `EndpointSignatureError` (no positional first parameter, or `*args`/`**kwargs`), `MissingPathArgumentsError` and `MisplacedHelperError` are raised **when the class is defined**, not when the method is called. Don't add call-time work that could be done here.
3. Picks the wrapper by the method's kind: an `async def` method (`inspect.iscoroutinefunction`, also `Endpoint.is_async`) gets an `async` wrapper, a `def` method a plain one. A stream decoder for the other kind of endpoint (a `StreamDecoder` on an `async def` endpoint, an `AsyncStreamDecoder` on a `def` one) raises `EndpointSignatureError` when the class is defined, naming the right decoder.
4. Records `wrapper -> endpoint` in `_registry.py`, so `ClientX`/`Resource` (name checks, prefixes), `clientx.tools` and tests can find an endpoint from its method with `endpoint_for(API.method)`. There's no public or process-wide registry: `Endpoint` and `URLPath` are internal, and listing a client's endpoints is `list_tools()`'s job.

The decorator protocols (`RawEndpointDecorator`, `DecodedEndpointDecorator` in `_decorators.py`) each have three overloads: `def` methods of a `ClientX` or `Resource`, `async def` methods of an `AsyncClientX` or `AsyncResource`, then the `def` overload again. Limiting each overload to its own kind of class means only one can match, even when `Any` is involved (an `-> Any` annotation, or `json_decoder`); if two matched, mypy would make the endpoint untyped (`def (*Any, **Any) -> Any`). That's why async resources are a separate class. When none matches, mypy reports the first overload's error and pyright the last's, so the repeated `def` overload keeps both checkers' messages for `def` endpoints as the docs quote them; pyright also reports `reportCallIssue` and `reportUntypedFunctionDecorator` at that decorator. `test_type_checker_messages_name_the_fix` reads each overload with `typing.get_overloads`.

**Class creation** (`_client.py`, `__init_subclass__`):
- `ClientX` (sync, `httpx2.Client`) and `AsyncClientX` (`httpx2.AsyncClient`) share the private generic `_BaseClientX[HttpClient]`: class defaults, settings and `repr`. `Resource` and `AsyncResource` share `_BaseResource`: prefix, tags, and binding to a parent. Each of the four bases has its own `__init_subclass__`, which calls a shared helper (`_set_up_subclass`, `_set_up_resource`).
- An endpoint in a subclass's body must be its base's kind: `def` for `ClientX` and `Resource`, `async def` for `AsyncClientX` and `AsyncResource` (`_check_endpoint_kinds`, `EndpointSignatureError`). A resource mounts only on a client or resource of its kind (`_check_mount` in `__set_name__`, `TypeError`), and a class can't subclass both kinds. Inherited endpoints were checked when their class was defined, and a mounted resource when it was mounted, so each check looks only at the class's own body.
- Subclasses of each base reject endpoints and mounted resources whose names the base already uses (`EndpointNameConflictError`; reserved names are `dir(base)` plus the annotations of the base and its own bases, in `_RESERVED_NAMES`). Keep the bases' surfaces small, since every attribute is a name endpoints can't use: that's why sending is the module function `send_request()`, not a method, and why `Resource` keeps its state in `__clientx_*__` dunders.
- `Resource` subclasses (`prefix=`, `tags=` class arguments; inherited when omitted) join the prefix onto the path of each endpoint defined in the class body and prepend their tags. Prefixes are absolute, not composed through nesting.
- A `Resource` instance mounted as a class attribute is a descriptor: instance access returns a copy bound to the client (or parent resource) via `__clientx_parent__`; class access returns the unbound resource.

**Call time** (the `wrapper` inside the decorator):
1. `client_of(self)` (`async_client_of` in the async wrapper) walks resource parents to the client (`UnboundResourceError` if a resource isn't mounted). The steps up to the request and after the response are shared by both wrappers: `_prepare` (deprecation, binding, building the request and its log details) and `_result` (decoding).
2. `endpoint.bind(self, args, kwargs, validate=...)` returns `inspect.BoundArguments`. With validation on (the endpoint's `validate_arguments`, or else the client's `__clientx_validate_arguments__`, default `False`), it first checks each argument the caller passed, before defaults are applied, against the parameter's full resolved annotation with `TypeAdapter.validate_python(value, strict=True)`, raising `ArgumentValidationError`. The validated value is discarded, so validation never changes the request. Each parameter's `TypeAdapter` is built on first use and cached in `Endpoint._validators`; unannotated parameters and types without a Pydantic schema (`PydanticSchemaGenerationError`) get `None` and are skipped.
3. `RequestFactory` (`_request_factory.py`) consumes the arguments through an `ArgumentCursor`, using the plan stored on the endpoint rather than reading annotations again. The client parameter is consumed first. Each argument can be consumed only once, and any argument left over is an error. It does this in two passes:
   - Path placeholders `{name}` are consumed first and rendered by `URLPath.format`: each value goes through `to_jsonable_python` (falling back to `str`), then is percent-encoded with no safe characters, and a whole `.` or `..` segment is encoded too, so a value can't change the path. A value that would change it anyway raises `PathValueError` (call time, before sending): `None` (it would render as `null`), an empty value (it would drop the segment), or an empty segment in a `{name:path}` value. `{name:path}` keeps slashes (each segment still encoded); `{{`/`}}` are literal braces; any other converter raises `PathTemplateError` when `URLPath` is built, i.e. when the class is defined. Path values are never encoded twice: don't pre-encode them in tests or examples.
   - Each remaining parameter is mapped to a request part, in this priority order: (a) the parameter name is itself a request part (`params`, `json`, `headers`, `data`, `files`); (b) a request-part helper in `Annotated` metadata: `Query(key)`, `Header(key)`, `Form(key)`, `Body()`, `File()`. They subclass the internal `Part`, which `AnnotationInfo.part` finds with `isinstance`, and each sets the class constant `request_part` (a `ClassVar`, not a dataclass field): a `RequestPartName` literal, which is also the httpx2 argument name. `Part` and the part names aren't public; users choose a part only by choosing a helper. Every helper also takes a keyword-only `description`, which `Part.__get_pydantic_json_schema__` adds to the JSON Schema (so `clientx.tools` and MCP get it with no code of their own; a field's `Field(description=...)` is applied after it and wins). `PathParam(description=...)` (deliberately not `Path`: a `pathlib.Path` import would shadow it, and on 3.12/3.13 `pathlib.Path(description=...)` only warns, so the description would silently vanish) is a `Part` with no request part: it only describes a path parameter, counts as the one helper for `_check_helpers`, raises `MisplacedHelperError` on a model field, and raises `EndpointSignatureError` if its parameter has no placeholder. That last check runs in `ClientX`/`Resource.__init_subclass__` (`_check_path_helpers`), not in `Endpoint.func`, because a `Resource` prefix can add the placeholder after decoration; (c) the value is a Pydantic model, which `ModelExtractor` expands field by field. Unannotated model fields go to JSON. Anything else raises `UnconsumableArgumentError`.
   - Models are dumped by `dump_model()`: `mode="json"` and `by_alias=True`, with any `DumpConfig` on top. So `AnnotationExtractor.from_base_model` maps serialization aliases too. Single keyed values go through `pydantic_core.to_jsonable_python`.
   - In `params`, `headers` and `data`, a value that isn't a mapping or a model is one named value. It goes under `Part.key`, or else under the parameter name or the dumped field name, with hyphens for headers (`_default_name`). This applies to parameters and to model fields. A parameter named after a part is always the whole part, as given.
   - The resulting part dicts are merged into copies (a caller's dict is never changed): dict values are shallow-merged and later parts win, silently: that's the documented rule (`docs/requests.md`), so don't add collision warnings back (#1). `None` values are dropped from `params`, `headers` and `data`, because httpx2 would send them as empty values or reject them as headers; `json` keeps `null`. Numbers and booleans in headers become JSON text (`2`, `true`). The result is a `RequestSpec(path, parts)`.
4. `send_request()` (`_client.py`; `asend_request()` for async endpoints) builds and sends the request on the wrapped `httpx2.Client` (or `AsyncClient`). Then, unless the endpoint's `raise_for_status` (or else the client's `__clientx_raise_for_status__`, default `True`) is off, a 4xx or 5xx response raises `httpx2.HTTPStatusError`: the wrapper checks `response.is_error`, then calls `_raise_status_error` (`_araise_status_error` for async) in `_decorators.py`, which must only get error responses. It reads and closes the response first, so the error keeps its body and a streamed response frees its connection; for a response that isn't streamed, httpx2 already did both. It's a check in the call path, not an httpx2 event hook, so user event hooks are untouched. The wrapper times the call and logs one DEBUG record on the `clientx` logger (`_logging.py`) after the response or the failure (which it re-raises). The record has fixed `clientx_*` attributes and must never include values (header values, bodies, query strings); `test/test_logging.py` checks this.
5. If a decoder was given, it runs on any response that wasn't rejected above, and its output is returned (`_decode` in `_decorators.py`). A `StreamDecoder`'s iterator is wrapped so the response closes when iteration ends, and an `AsyncStreamDecoder`'s async iterator the same way (`_aresult`, `_astream`, `_aclose_when_done`, which also closes the decoder's own generator, as `yield from` does for the sync one); a `StreamResponseDecoder` hands the open response to the caller. Without a decoder, `None` returns nothing and `Response` returns the raw (already read) response.

`_annotation_extractor.py` normalizes `Annotated` metadata from function signatures and from Pydantic `FieldInfo`/computed fields, including aliases, into `AnnotationInfo`/`NamedAnnotation`. It expands PEP 695 `type` aliases, plain and generic (`_unwrap_type_alias`), and puts the metadata of nested `Annotated` first, the way Python flattens it. Both the signature path and the model path use it, and both run `_check_helpers`: a helper must be the only one, in the outermost `Annotated`, so one nested inside another type (`Annotated[int, Query()] | None`, `list[Annotated[...]]`) or a second helper raises `MisplacedHelperError`. That's a deliberate rule, not a limitation to work around: different request parts mean different endpoints. `Endpoint.func` runs the check, so parameters fail when the class is defined. Model fields fail then too when a parameter is annotated with a complete model class, and otherwise when the model is sent. `model_annotations(model_type)` caches each model class's field annotations (bounded `lru_cache`, read-only mappings), so a model is analysed once, not on every call.

`ClientX.__init__` forwards `**kwargs` to `httpx2.Client`, and `AsyncClientX.__init__` to `httpx2.AsyncClient`. They are typed by the `HttpxClientKwargs` and `AsyncHttpxClientKwargs` TypedDicts in `_client_types.py`, which share `_HttpxClientOptions` and differ only in `transport` and `mounts` (async transports for `AsyncClientX`), whose option types mirror httpx2's private aliases (`httpx2._types`, such as `QueryParamTypes`) so each option accepts what `httpx2.Client` does. `test_client_options_accept_every_form_httpx2_accepts` in `test/test_typing.py` passes each form, so a narrower copy fails `make typecheck`. `DumpConfig`, the TypedDict of `model_dump` options the helpers take as `dump_config=`, sits next to it; each has a test in `test/test_clientx.py` that checks its keys against the library's signature. The `httpx2.Client` is internal (`__clientx_client__`), with no public `client` or `user_agent` attribute, so those names are free for endpoints and a client's configuration can't change after it's created; `close()` and `with` close it (`aclose()` and `async with` for `AsyncClientX`). A subclass ships defaults as class arguments, `class ExampleAPI(ClientX, base_url=..., user_agent=...)`, stored in `__clientx_base_url__` and `__clientx_user_agent__` (no new public names); arguments given to `__init__` win. The `User-Agent` comes from `user_agent=`, else `headers=`, else the class, else `ClientX/<version>`.

`tools.py` (public, `clientx.tools`) turns a client's endpoints into AI tools: it walks the client's class (and mounted resources) with `_registry.endpoint_for`, builds an argument model per endpoint (internal field names with parameter-name aliases, so `json` can't clash with `BaseModel`), and serializes results to JSON-friendly values. It must stay free of AI-SDK dependencies; protocol adapters build on it. `Tool.call()` calls a `def` endpoint and `await Tool.acall()` an `async def` one (`Tool.is_async`); each raises `TypeError` for the other kind. `list_tools()` takes either kind of client and recurses into `Resource` and `AsyncResource`.

`mcp.py` (public, `clientx.mcp`, needs the `mcp` extra; `mcp` is also in the dev group so CI tests it) serves `list_tools()` over MCP with the SDK's low-level `Server`, using the core's schemas as-is (one source of truth). Its `read_only` filter defaults to `True`, unlike `list_tools()`'s, so a server exposes endpoints that change data only when asked; tests that need write tools pass `read_only=False`. Non-object output schemas are wrapped as `{"result": ...}` with `$defs` moved to the top. Tests talk to it in-process with `mcp.Client(server)`. A tool call awaits `Tool.acall()` for an async client's tools, and runs `Tool.call()` with `anyio.to_thread.run_sync` for a sync client's, so a blocking call never stalls the server's event loop.

`examples/beeceptor/`, `examples/jsonplaceholder/` and `examples/oauth2/` (an OAuth 2 client credentials `Auth` class, against Duende's public demo server) contain complete example clients, run by the `examples/*_example.py` scripts; `examples/jsonplaceholder/jsonplaceholder_async_client.py` is an `AsyncClientX` for the same API, run by `examples/jsonplaceholder_async_example.py`. All call live public APIs, so the scripts need network access; lint and typecheck cover them, but the test suite doesn't run them. `examples/ruff.toml` sorts their imports the way a user's project would, with `clientx` among the third-party packages and the example packages first-party, so they're correct to copy. Write the snippets in the README, `docs/`, and `llms.txt` the same way: `clientx` imports go in the third-party block, next to `httpx2` and `pydantic`.

`llms.txt` (repo root) is a compact guide for AI coding assistants. Keep it in sync with the public API and the docs; its code sample must run and type-check.

The README is the PyPI page, so it stays short: an overview, install, a quickstart, and links to the guide. The guide is in `docs/`, one Markdown page per topic, which the docs site (#13) will build from. The README links to the guide with absolute GitHub URLs, because relative links break on PyPI; pages in `docs/` link to each other relatively. The README's header shows the logo, `docs/assets/logo-light.svg` and `logo-dark.svg`, with a `<picture>` element that picks one for GitHub's color mode; its absolute `raw.githubusercontent.com` URLs work once the repository is public.
